# 长期记忆与 `forge_memory`

长期记忆保存在当前 `FORGE_HOME`（或显式 `stateDir`）下的共享 SQLite 数据库中。已有事实用 `update_memory` 直接创建/更新；只有需要从历史会话重新提炼时才调用 `forge_memory`。记忆是参考数据，不是权限来源，也不证明当前文件状态。

## 更快的聚焦整理

`forge_memory` 保持一次显式模型请求，使用当前会话的模型，不自动重试、续写或切换模型。建议每次一个主题：

```json
{
  "query": "整理 Forge 本机更新方式，只保留已确认的长期约定",
  "keywords": ["本机更新", "编译"],
  "scope": "workspace",
  "max_memories": 2,
  "dry_run": true
}
```

- `max_memories`：最多提议多少条记忆，默认 **4**，范围 **1–12**。数量包含创建和更新，并不是保证生成的数量。模型超过请求数量时整批拒绝，不静默丢弃多出的条目。
- `scope`：默认仍为 `all`，包含其他工作区、归档和子会话；`workspace` / `session` 缩小历史会话范围，但不隔离共享记忆库。
- `keywords`：任意字面关键词命中即可；中文建议明确提供。省略时仅按空白及部分标点拆分 `query`，不提供语义搜索、时间条件或否定条件解析。
- `tags`：过滤已有记忆，不作为会话过滤条件，也不强制成为输出记忆的标签。
- `dry_run`：同样检索、调用模型、校验和计入用量，只是不写数据库。它不是低成本模式，也不会绕过生成错误。

提示词要求优先生成简洁的新事实，摘要目标少于 160 字符，详情目标少于 1,200 字符，不复制完整工作日志。目标长度不是对旧记忆的截断指令：更新仍要保留有效信息。原有输出硬限制保持为 64,000 字符 / 96,000 UTF-8 字节，单条详情最多 32,000 字符。

## 异步调用与自动通知

显式设置 `background:true` 后，完成本次权限审批即返回任务 ID，主 agent 可以继续其他工作，甚至先结束当前运行。后台合成保留启动时的会话模型，不自动重试；结果持久化后，通过输入队列唤醒主会话读取结果。子代理发起的任务也通知其主会话。

```json
{"query":"整理 Forge 开发约定","keywords":["Forge","约定"],"scope":"workspace","max_memories":2,"background":true}
```

用 `async_task` 的 `list/read/wait/stop/wake` 管理任务；`wake` 只幂等重试结果通知，不重新合成。`background` 默认 `false` 保持同步兼容。异步用量保存在任务上，不迟到修改已结束 run 的统计。暂停/失败的主会话不会被通知自动恢复；Core 停止后不自动重做中断任务。

完整协议、权限、容量、恢复边界及未来工具接入方式见 [通用异步工具](ASYNC_TOOLS.md)。

## 证据预算与长记忆

扫描上限保持 500 个会话、50,000 条非 system 记录、32,000,000 字符；会话候选最多 60 条。检索阶段每条记录只做一次小写转换和关键词位置查找，已有记忆的相关度只计算一次。

普通选中证据的序列化预算由 48,000 降至 **24,000 字符**，会话片段由 1,800 降至 **1,200 字符**。同会话中投影文本与来源角色/用户 origin 完全相同的记录只保留最新的一条；只共享截取片段、来自不同会话或不同角色的记录不会合并。

已有记忆先按最多 6,000 字符参与选择，再按选中顺序尝试补全这些长记忆。只有补全这些记忆可以使用 **48,000 字符**的扩展总预算，不会用这部分预算继续塞入无关会话。预算包括序列化转义开销；无法补全的记忆仍标为 `truncated: true`、对模型标为 `can_update: false`，禁止覆盖。已有记忆的版本在提交事务内再次检查。

以上是证据预算，不包括系统提示词、查询及覆盖统计；不是 Provider 的 token 上限。较小的输入和输出目标减少模型工作量，但不保证固定响应时间或上游一定不截断。

## 引用协议与校验

合成模型使用本次请求的短引用 `E1`、`E2` 等，主机保存到真实会话记录 / 记忆版本的映射。会话分组使用临时 `S1`、`S2`，保留 `mN` 序号、角色、工作区及会话更新时间，避免丢失同会话内的顺序信息；分组和序号不是可用引用。

模型输出里的引用只接受实际提供的证据映射（也兼容同一证据的精确规范长引用，允许首尾空白）。正文中提到的其他引用不会变成可用证据；不会用模糊匹配、大小写转换或猜测补救。相同证据的短/长引用会合并为一个真实来源。返回值的 `evidence[].ref` 仍是规范长引用，`alias` 是本次短引用，数据库不保存临时别名。

只容忍**完整 JSON 外面单独包了一层 JSON/裸代码围栏**这一无损格式差异。不会提取混杂说明中的 JSON、拼接多块输出或修复不完整 JSON。字符/字节限制在剥离围栏前检查。JSON schema、来源、敏感内容、更新完整性和版本检查仍全部生效。

任何一条提案校验失败都不会提交其他条目。模型调用不持有 SQLite 写事务；通过校验后才在一个事务中统一创建/更新。取消、权限下降和版本冲突继续阻止提交。引用存在性校验不等于对模型结论做了独立事实核验。

## 结果与失败诊断

- `coverage` 保留扫描/选择/片段截断标志，并包含 `duplicateRecords`、`expandedMemories`、`selectedEvidence` 和 `evidenceChars`。
- 成功完成合成时，`synthesis` 包含 `modelRequests`、模型用户输入的 `inputChars`、`outputChars` 和提案数 `proposals`。没有命中证据时不会调用模型。
- `output_truncated` 表示上游未完成输出，错误附带输入规模，并建议缩小主题或使用 `max_memories: 1`；不要原样无限重试。
- `unknown_reference` 会指出从 1 开始的 `proposal` / `ref_index`，不回显可能包含私密数据的错误引用。
- `incomplete_update` 表示未引用完整旧记忆；缩小主题后重新检索，或用 `get_memory` 分页读全并通过 `update_memory` 携带当前 `expected_version` 更新。
- 诊断只包含受控错误类别和数量/位置，不输出原始 Provider 响应、模型文本或密钥。

这是有界、聚焦的整理，不应宣称覆盖全部历史。更小的证据预算可能减少单次覆盖面；需要更全面整理时应明确拆分主题，而不是把多次后台合成伪装成一次请求。
